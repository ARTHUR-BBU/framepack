# Framepack 0.4 Beta Product State Cutoff

Cutoff ID: `BETA-CUTOFF-12`

Date: 2026-05-24

Purpose: close the current Framepack 0.4 beta product state as a documented, testable baseline before the project moves into feedback-driven beta patches.

## Current Published State

- npm package: `framepack@0.4.0-beta.1`
- npm beta tag: `0.4.0-beta.1`
- npm alpha tag: `0.4.0-alpha.4`
- npm latest tag: intentionally not advanced from `0.4.0-alpha.1`
- GitHub prerelease: `v0.4.0-beta.1`
- Recommended install path for beta testers: `npm install framepack@beta --no-audit --no-fund`

This cutoff does not republish the package. It records the product line that has already been published and verified.

## Closed In 0.4 Beta

The following product surfaces are closed enough to be treated as the current beta baseline:

- agent-first installation guidance through `init-agent`
- Codex and Claude Code project onboarding files
- MCP discovery through `framepack mcp --describe`
- MCP server startup through `framepack mcp`
- workflow packs and creative direction packs
- conservative pack recommendation
- Animation Capability Atlas
- capability stack recommendation
- package protocol v1 documentation and validation
- `CAPABILITY_GRAPH.json` as the package sense filter
- `RUNTIME_MANIFEST.json` as runtime memory
- `ASSET_EXECUTION_PLAN.json` with source and forge execution kinds
- backend-neutral Asset Forge Layer contracts
- `agent-sprite-forge` recommendation without hard dependency
- HyperFrames `0.6.40` runtime compatibility
- runtime doctor, lint, inspect, and snapshot command surfaces
- release smoke, installed-package smoke, real scenario rehearsal, and release gate scripts
- beta feedback collection and triage loop

Closed means the surface has a documented contract and regression coverage. It does not mean every future workflow is complete.

## Deliberately Not Closed

The following items remain outside the beta baseline and must not be implied by docs, release notes, or agent handoff:

- automatic installation of `agent-sprite-forge` skills
- automatic detection of every external skill, plugin, MCP server, or model account
- hosted video model integration for Seedance, Gemini Omni, Kling, or similar systems
- a community capability registry
- full visual template marketplace or creator ecosystem
- long-running MCP task persistence
- finished rendered-video guarantees when assets, HyperFrames runtime, or visual QA evidence are missing
- automatic asset production for forge tasks

These are valid future directions, but they should enter through explicit design docs, tests, and beta patch notes.

## Operating Rules After This Cutoff

- Do not mutate the published `0.4.0-beta.1` artifact.
- Ship fixes through a new beta version such as `0.4.0-beta.2`.
- Keep `latest` unchanged until there is a separate stable-release decision.
- Every patch that changes CLI, MCP, package protocol, install behavior, runtime behavior, or package generation needs focused regression coverage.
- Run `npm run release:gate` before any packaging or install-surface beta patch.
- Use `BETA-FEEDBACK-11` reports as the main input queue for beta patches.
- Report agent trials with concrete evidence: version, commands, generated package path, validation result, readiness, next actions, runtime status, and visual evidence status.

Phase report: [`beta-patch-radar-v0.4.md`](beta-patch-radar-v0.4.md)

The next phase is not another broad architecture expansion. It is a feedback radar:

- separate P0/P1 patch candidates from P2/P3 polish
- decide whether a `0.4.0-beta.2` patch is needed
- keep architecture exploration behind documented capability contracts

## Plain-Language Summary

Framepack 0.4 beta is now a real published product line, not just a local experiment. This cutoff says: here is what the beta can already do, here is the evidence, here is what we are not pretending to do yet, and here is how we will decide the next patch. For a new user, the simple version is: install `framepack@beta`, let your coding agent initialize the workflow, generate a package, validate it, inspect status, and report anything confusing with evidence.
