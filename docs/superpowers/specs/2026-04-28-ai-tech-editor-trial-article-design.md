**写作定位**：技术趋势洞察者 + 工作流搭建者的结合

1. **认知价值**：理解"写视频"和"生成视频"是两个完全不同的范式

**目标读者**：泛 AI 爱好者（技术人和非技术人都能读下去）

### H 部分：Hook 开头（~400 字）

**设计要点**：
- 个人场景切入：写完技术笔记想变成视频的真实经历
- 真实痛点罗列（有据可查，不夸张）：
  - Seedance 2.0 画面震撼但文字渲染乱码
  - Kling 3.0 画面逼真但文字、图表、动画组合无法精确控制
  - Veo 3.1 原生音画同步但对信息型视频的精确排版无能为力
  - 核心困境：标题无法在第 3 秒精准出现、数据图表无法按真实数据生长、标注箭头无法平滑移入
- 范式冲突引出：这不是调参数的问题，这是两类完全不同的视频需求
- "生成" vs "写" 的概念引入
- HeyGen 开源的 HyperFrames 作为转折点出现

**写法要求**：
- 不用夸张修辞（如"3 小时白费"），用精准的痛点描述
- 每个痛点都有行业证据支撑（AI 文字渲染不稳定是公认痛点、VBench-2.0 专门评估可控性维度）
- 幽默不油，吐槽真实

### K-1 部分：HyperFrames 到底是什么（~400 字）

**核心信息**：HyperFrames 不是又一个 AI 视频生成工具，而是 HTML 原生的视频渲染框架。

**关键对比表**：

| 传统 AI 视频工具 | HyperFrames |
|---|---|
| 输入：自然语言提示词 | 输入：HTML/CSS/JavaScript |
| 输出：不可预测的画面 | 输出：精确到像素的视频 |
| 文字经常渲染错误 | 文字是真实 DOM，100% 准确 |
| 动画靠模型"猜" | 动画用 GSAP/CSS 精确控制 |
| 适合：电影感画面 | 适合：信息型、结构型、数据型视频 |

**核心洞察**：
- HyperFrames = "排版引擎"（不是"画师"）
- HeyGen 不是在做 Sora 竞品，而是开辟新赛道：Agent 原生视频工程
- HTML 是 AI Agent 生成视频最自然的中间语言（LLM 最擅长写 HTML）

**写法要求**：
- 用类比开门（画师 vs 排版引擎）
- 表格让对比一目了然
- 技术准确但用人话

---

### K-2 部分：HyperFrames 很棒，但它只解决了一半问题（~300 字）

**核心信息**：HyperFrames 是渲染引擎（厨房设备），但扔一段内容进去，它不知道怎么做菜。

**类比设计（预制菜比喻）**：
- HyperFrames = 厨房设备（灶台、烤箱、刀具齐全）
- 但你给它一袋食材说"做道菜"：食材怎么切？按什么顺序下锅？每道工序多少时间？
- 缺的不是设备，是"菜谱 + 备料方案"

**具体痛点**：
- Markdown 文档 → 怎么拆成场景？每个场景多长？
- 网站 → 哪些部分要截图？放在视频哪个位置？
- 哪些素材已有？哪些还需生成？
- 怎么确保时长、节奏、结构合理？

**写法要求**：
- 预制菜比喻贯穿，轻松易懂
- 痛点具体不空泛
- 为 K-3 的 Framepack 登场做铺垫

### K-3 部分：所以我和 AI 搭档造了一座桥 —— Framepack（~400 字）

**核心信息**：Framepack 是视频项目编译器，把内容源自动编译成 HyperFrames 可执行的视频工程包。

**叙事切入**：第一人称，"我和 AI（Codex）搭档造了 Framepack"

**类比**：写 C 代码 → 编译器 → 机器码；给内容 → Framepack → 视频工程包

**Framepack 核心能力（不求全，求准）**：
1. **内容摄入**：Markdown、网站 URL、Thread 帖子都能吃
2. **自动分镜规划**：内容 → 带时间线的场景方案
3. **素材执行计划**：自动识别已有/待生成素材，规划生成方式
4. **质量护栏**：内置验证报告，确保时长、结构、素材完整性
5. **工程包输出**：可审查、可修改、可迭代的中间工程

**关键定位**：Framepack 不生成最终视频，它生成"视频的制作方案 + 工程骨架"。

**写法要求**：
- 第一人称有温度
- 编译器类比简洁有力
- 能力列举清晰不过度
- 强调"做出来"和"做得好"的差距

### K-4 部分：实操展示 —— 从一条 Thread 到一个视频工程包（~500 字）

**核心信息**：3 条命令，从原始内容到完整工程包。

**CLI 流程**（来自项目 README 真实命令）：

```bash
# 第一步：从 Thread 文件生成视频工程包
npx framepack generate \
  --thread-file examples/thread.txt \
  --output-dir out \
  --goal "Explain the thread" \
  --audience "Founders" \
  --project-name thread-case

# 第二步：自动捕获和生成所需素材
npx framepack capture --project-dir out/thread-case
npx framepack sync-assets --project-dir out/thread-case
```

**输出工程包结构**：

```
out/thread-case/
├── PACKAGE_MANIFEST.json       ← 工程包索引
├── VIDEO_BRIEF.json            ← 视频制作大纲
├── SCENE_PLAN.json             ← 分镜方案（时间线+场景）
├── SCRIPT.md                   ← 旁白脚本
├── STORYBOARD.md               ← 分镜描述
├── ASSET_PLAN.json             ← 素材清单
├── ASSET_EXECUTION_PLAN.json   ← 素材执行计划
├── VALIDATION_REPORT.json      ← 质量验证报告
├── HANDOFF.md                  ← 交接文档
├── assets/                     ← 素材目录
└── compositions/               ← 视频合成结构
```

**前后对比**：
- **没有 Framepack**：手动规划场景、管理素材、写 HTML composition、检查时长和结构
- **有 Framepack**：一条命令，从原始内容到完整工程包，每个环节有结构化文档可审查和修改

**写法要求**：
- 用真实命令和输出，经得起验证
- 前后对比突出 Framepack 的价值增量
- 不铺陈代码，点到为止，让读者感受到"原来这么简单"

### R 部分：工具边界 + 趋势升华 + 行动号召（~300 字）

**第一层：工具边界表**

| 你想做什么 | 用什么工具 | 为什么 |
|---|---|---|
| 电影感的画面 | Seedance/Kling/Veo/Sora | 它们是"画师" |
| 真人+对话+原生音效 | Veo 3.1 | 目前唯一原生音画同步 |
| 产品发布讲解视频 | HyperFrames + Framepack | 精确文字+结构化+可批量 |
| 知识卡片/教程视频 | HyperFrames + Framepack | HTML 天然擅长排版+动画 |
| 数据可视化视频 | HyperFrames + Framepack | 真实数据+真实图表 |
| 一条推文变一条视频 | HyperFrames + Framepack | 自动分镜+素材生成 |

**设计意图**：这张表解决"我到底该用啥"的普遍困惑，是全文转发概率最高的部分。

**第二层：趋势升华**

- "生成视频"和"写视频"不是竞争关系，是互补关系（类同 Photoshop vs Figma）
- Agent 原生视频是独立赛道：未来不是"打开视频编辑器"，而是"给 Agent 内容，它编译成视频"
- Framepack 是这条路上的一块砖

**第三层：行动号召**

```
Framepack 已经在 GitHub 开源了。
仓库里有完整的 Quickstart，三条命令就能跑起来。

如果你也觉得"写视频"比"生成视频"更适合你的场景，
去试试，顺手点个 star。

这不是终点。
这是 Agent 原生视频工作流的起点。
```

**写法要求**：
- 工具边界表清晰有力
- 趋势判断不浮夸，有据可依
- 行动号召简洁，降低门槛（三条命令就能试）

## 五、全文调性规范

**调性关键词**：类比驱动、幽默不油、专业不装、清晰即力量

**具体规则**：
1. **类比驱动**：画师/排版引擎、厨房/预制菜、编译器 —— 每个技术概念都有生活化的类比
2. **幽默不油**：痛点吐槽真实不夸张，不说"3 小时白费"，说"文字是乱码，标题糊了"
3. **专业不装**：技术部分准确（CLI 命令、类型定义、输出结构都是真实的），但用普通人读得下去的语言
4. **清晰即力量**：工具边界表、前后对比、类比映射 —— 让读者看完觉得"终于搞清楚了"
5. **第一人称贯穿**：不是教科书，是一个在玩 AI 的人的真实经历
