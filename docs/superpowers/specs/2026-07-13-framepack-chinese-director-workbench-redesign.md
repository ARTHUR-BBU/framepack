# Framepack 中文导演工作台重设计

## 1. 目标

Framepack 的 Codex 第一版必须从“开发者操作面板”重做为普通用户能直接理解的中文导演工作台。

用户只需要完成五件事：说清想法、提供素材、确认导演方案、观看动态样片、决定是否交给 HyperFrames。构建、快照、技术检查、武器加载和交接文件生成都属于后台工作，不应以英文命令或开发术语暴露给用户。

本次重设计同时修复一个产品判断错误：当前系统虽然能跑通 HTML 构建、快照、技术审计和 handoff 管道，但仍是固定英文模板，尚未把用户需求、素材、审美策略和动画武器真正编排进画面。因此它是可运行的工程底座，不是已完成的导演产品。

## 2. 产品体验

### 2.1 用户心智

Framepack 是一间有经验的中文导演室：

- 用户说“我要做什么片子”，不需要先理解工程概念。
- Framepack 主动追问缺少的关键信息和素材。
- Framepack 用简短中文解释它准备怎么拍，而不是把内部 Markdown 或 JSON 倒给用户。
- 用户能随时说“太科技了”“节奏慢一点”“产品再突出”，导演方案和样片随之更新。
- Framepack 提建议，用户最终决定返工、补素材、接受风险或交接。

### 2.2 主界面

采用已确认的“导演驾驶舱”，但面向普通用户重新组织：

```text
┌──────────────────────────────────────────────────────┐
│ Framepack 导演台       当前项目：未命名影片     已保存 │
├──────────────┬───────────────────────┬───────────────┤
│              │                       │               │
│  导演对话     │      动态样片舞台       │   导演判断     │
│              │                       │               │
│ 说出视频想法  │    播放、暂停、定位      │  当前进度      │
│ 拖入本地素材  │    对比修改前后          │  发现的问题    │
│ 调整风格节奏  │    查看关键证据帧        │  推荐下一步    │
│              │                       │               │
├──────────────┴───────────────────────┴───────────────┤
│  分镜时间线：开场 ───── 产品证明 ───── 收束与行动号召   │
└──────────────────────────────────────────────────────┘
```

第一屏的唯一主问题是“今天想做一支什么样的片子？”。当用户尚未提供素材时，样片区显示克制的舞台占位和素材提示，不显示虚假的默认成片。

### 2.3 Codex 与浏览器的交互边界

Codex 对话是第一版的主要沟通入口，浏览器是导演方案、素材、样片和审片结果的可视工作台。第一版不伪造一个无法唤醒 Codex 的网页聊天框：

- 用户在当前 Codex 对话中说需求、补充意见和要求修改。
- Codex Host Orchestrator 把这些对话动作写成版本化导演事件，并调用本地导演引擎。
- 浏览器实时读取同一项目状态，展示“Codex 正在理解需求 / 整理素材 / 制作样片”等中文进度。
- 浏览器内的批准、带理由接受风险和确定性任务按钮直接写入项目事件；需要创意推理的动作会明确提示用户回到当前 Codex 对话，不假装网页本身拥有 Codex 能力。

未来只有在 Codex 提供正式的双向浏览器桥接能力，或项目显式配置独立模型 API 后，才增加浏览器内原生导演对话。不得借用未声明的本机凭据，也不得把固定规则输出冒充 Codex 推理。

### 2.4 五个连续状态

1. **说想法**：目标、受众、比例、时长、发布场景和一句话要求。
2. **备素材**：拖入产品图、视频、品牌资料、网页或参考片；明确已有、缺少和可替代素材。
3. **定方向**：用中文展示视觉调性、情绪节奏、场景提纲、导演手法和避免事项。
4. **看样片**：播放真实 HTML 动态样片，查看分镜时间线、关键证据帧和修改记录。
5. **做决定**：清楚区分技术问题与审美建议，允许返工、补素材、批准或带理由接受风险。

这些状态是同一个驾驶舱的渐进变化，不是五个互不相干的后台页面。界面始终只突出当前最重要的一个动作。

## 3. 中文与视觉标准

### 3.1 视觉命题

“专业导演暗房”：深墨黑的工作空间、暖白内容、克制的朱砂色行动提示；像剪辑室与分镜桌的结合，安静、有判断力，不像常见 SaaS 仪表盘。

### 3.2 设计规则

- 样片舞台是最大视觉主体，不能被按钮和卡片淹没。
- 不使用卡片拼盘、霓虹渐变、发光边框或多个竞争性强调色。
- 使用留白、字号、对齐和分割线建立层级；卡片只用于真实可交互对象。
- 中文界面采用本地化字体，渲染和浏览都不依赖在线字体。
- 用户可见文案使用日常中文；`build`、`snapshot`、`audit`、`handoff` 等词只留在日志或高级详情里。
- 正常状态用暖灰，当前动作使用朱砂色，成功使用低饱和青绿，风险使用琥珀色，技术阻断使用暗红。
- 动效服务于工作状态：页面进入、样片切换、导演判断出现三类动效足够；禁止装饰性循环动画。

### 3.3 中文状态词

| 内部状态 | 用户看到的中文 |
|---|---|
| draft | 等待你的想法 |
| intake | 正在整理素材 |
| direction | 等你确认导演方向 |
| building | 正在制作动态样片 |
| review | 样片等待审阅 |
| revise | 正在按意见修改 |
| approved | 样片已经确认 |
| handed_off | 已交给 HyperFrames 制作 |
| technical_fail | 制作条件尚未满足 |

## 4. 旧版核心资产继承

### 4.1 继承原则

旧版不是整包迁移，而是像老电影厂搬迁：剧本手册、经过试拍的镜头语言和有来源的道具可以带走；旧厂房的电线、门禁和 Hermes 专用传声筒留在历史里。

每一项继承资产必须记录：历史来源、许可证或来源说明、当前维护者、HyperFrames 兼容性、可执行入口、验证证据和状态。没有来源或没有真实视觉验证的资产只能进入候选区，不能被导演自动选用。

新分支完成迁移后，旧 `framepack-plugin/`、`framepack-e2e-test/`、Hermes hooks、Python plugin runtime 和部署脚本不得留在当前工作树。它们继续存在于 Git 历史，选择性继承的内容进入新的宿主无关目录并登记来源。CI 必须使用目录 denylist、依赖扫描和文本/import 扫描，阻止新代码重新依赖旧 Hermes 运行时。

### 4.2 四类资产

#### A. Skills：导演最佳实践说明书

旧版已有 8 套技能说明：

- `framepack`：意图分诊、共创阶段和总工作流。
- `framepack-director`：素材收集、视觉方向、节奏、分镜和故事圣经。
- `framepack-animation-library`：动画武器目录、参数、调用方式和 Execution Manifest。
- `framepack-arsenal`：武器注册、来源、哈希、下载、闲置和复用生命周期。
- `framepack-gsap`：HyperFrames 安全的 GSAP 配方。
- `framepack-reference-miner`：参考视频的场景、运动、色彩、音频和内容 DNA 提取。
- `framepack-sprite-forge`：精灵图规划、后处理及与 sprite 武器的交接。
- `framepack-production-quality`：质量检查、严重级别和生产修改原则。

新版把 skills 视为核心运行资产，而不是旁边的说明文档。导演引擎每次执行必须留下 `skill-load-plan`：本次任务匹配了哪个工作流、实际读取了哪些说明、哪些未使用以及原因。Codex 只按需加载相关 skill，禁止一次性把全库塞进上下文。

旧 skill 中的 Hermes hooks、部署命令、版本号和宿主专属行为不得继承。可复用内容要拆成宿主无关的短技能与引用文件，再由 Codex 工作流调用。

#### B. 审美与调性资产

优先继承并重新验证：

- 8 种 Visual Styles：Swiss Pulse、Velvet Standard、Deconstructed、Maximalist Type、Data Drift、Soft Signal、Folk Frequency、Shadow Cut。
- 12 个 Director Taste Moves，例如物件崇拜、杂志重拳、爆发前静默、界面编舞和数据圣殿。
- 7 个 Kinetic Grammar，例如因果显形、回声变形、遮罩开门、蓄力释放和吸气—出拳—停顿。
- 10 个 Surprise Operators，例如尺度冒犯、节奏断裂、留白震荡、母题变异和突然凝固。
- Reference DNA、Visual Physics、Recurring Motif、Negative Prompt 和 Kinetic Continuity 的表达方法。

这些内容不是模板名称菜单，而是导演推理材料。每个视频最多选择 1 个主调性、1 个辅调性、1–3 个导演手法和 0–2 个惊喜操作，避免风格堆砌。

#### C. 动画武器库

现有可盘点资产为：17 件 Part 原子武器、5 件 Block 场景武器、1 套 SaaS 产品发布模板和 1 个 anime.js 适配层。

17 件 Part 包括文字分裂、字幕擦除、模糊遮罩、数字跳动、胶片漏光、3D 卡片悬浮、网格揭示、SVG 形变和精灵帧动画等。5 件 Block 包括卡片级联、编辑级数据图表、3D 设备展示、便利贴流程图和旧转场包。

不能把“目录里有文件”等同于“武器可用”。目前只有 `caption-clip-wipe` 具备较完整的 preset 与视觉 scorecard；其他武器大多只有代码和说明，尚缺统一的实际试拍证据。新版迁移采用四级状态：

1. `candidate`：找到历史资产，尚未复验。
2. `compatible`：通过静态契约与 HyperFrames lint/check。
3. `proven`：有 16:9 与 9:16 的真实样片、关键帧和视觉评分。
4. `preferred`：在真实项目中验证，可被导演自动优先选择。

`transitions-pack` 已在旧版标记为 deprecated，不进入自动推荐；转场优先使用最新 HyperFrames 原生能力。

#### D. 模板、参考片与生产工具

- `miara-style-template` 可作为迁移验证样本，包含本地字体、GSAP、约 50 张 PNG 资产和历史快照，但必须先核对来源说明、品牌专属性和可泛化程度。
- Reference Miner 的 5 个分析脚本可作为新参考片工作流候选，不直接原样嵌入导演引擎。
- Sprite Forge 的布局图与透明精灵图后处理流程可保留为专用工具链候选。
- 历史快照可用于回归比较，不能直接冒充新项目的审片证据。

迁移数字以实际可执行文件为准：23 件可执行动画/模板资产（17 Part + 5 Block + 1 Template），另有 1 个 anime.js 适配层。旧 MOC 中的规划项不计入已存在资产；deprecated 的 `transitions-pack` 只进入迁移账本，不进入推荐库。

## 5. 新导演工作流

```text
中文需求 + 本地素材
    ↓
Codex Host Orchestrator：记录用户意图与事件
    ↓
意图分诊：选择相应 workflow skill
    ↓
素材体检：真实读取、去重、识别缺口
    ↓
导演提案：调性 + 视觉物理 + 节奏 + 分镜 + 避免事项
    ↓
Skill Load Plan + Weapon Load Plan
    ↓
Preview Composer：按分镜和素材生成项目专属 HTML 样片
    ↓
HyperFrames lint/check + 真实快照
    ↓
技术审计 + 审美审片 + 素材使用核对
    ↓
用户返工 / 补素材 / 批准 / 带理由接受风险
    ↓
Handoff Manifest → HyperFrames
```

关键约束：

- 用户的标题、文案、素材和已确认调性必须实际出现在 storyboard 与样片中。
- 没有素材时必须显示“缺少素材”，不得把空目录判定为素材使用充分。
- 选中的武器必须在最终 HTML 中实际调用；只写进清单不算使用。
- 手写动画是最后手段，必须记录查过哪些官方能力和武器、为何不能复用。
- 审美评估必须引用真实快照与素材账本，不能只看 Markdown 自我评价。
- 用户修改需求、替换素材、调整调性或重新构建后，旧快照、审片、批准和豁免必须自动失效。

## 6. 系统边界

新版分为六个独立层：

1. **Codex Host Orchestrator**：把当前 Codex 对话转换成项目事件，选择任务、装配相关 skills、管理取消与重试，并把结果同步给工作台。
2. **中文工作台**：只负责项目状态、素材、导演方案、预览和决策呈现。
3. **导演引擎**：负责意图、素材、调性、分镜、版本和用户决策状态。
4. **Skill 与 Arsenal 运行时**：负责按需加载最佳实践、匹配武器、记录来源和验证状态。
5. **Preview Composer**：唯一负责把已确认的导演方案、素材和武器计划编排成 HyperFrames HTML；输出构建报告、实际武器调用收据和内容哈希。
6. **HyperFrames Bridge**：负责结构检查、lint/check、快照、渲染计划与最终生产交接。

Preview Composer 的输入是已验证的 project spec、素材账本、storyboard、frame/taste spec、skill-load-plan 和 weapon-load-plan；输出是本地化 `index.html`、构建 ID、调用收据与错误列表。缺素材、武器加载失败或输入版本不一致时必须失败并回到对应上游状态，不能生成通用模板兜底。

Codex Host Orchestrator 每次任务必须记录：用户事件、实际加载的 skill 文件与哈希、允许调用的本地命令、开始/结束时间、取消或重试次数、产出文件和失败原因。`skill-load-plan` 只是计划；只有实际读取收据和由此产生的项目差异才能证明 skill 被执行。

浏览器工作台不得复制导演 pipeline。所有操作通过版本化 API 调用同一个导演引擎。未来 Hermes 或 Claude Code 只能新增宿主适配层，不得重写业务逻辑。

### 6.1 状态与版本失效

每个 storyboard、构建、快照、审片、批准、豁免和 handoff 都绑定同一个 content hash。该 hash 至少覆盖用户简报、素材文件哈希、调性、分镜、实际加载的 skill 与 weapon 文件哈希、weapon plan、HyperFrames 版本、本地 vendor/font 哈希、Composer 配置与 Composer 版本。

任何上游内容变化都会创建新 build ID，并自动使旧的 snapshots、audit、approval、waiver 和 handoff 变为 `stale`。旧证据保留供比较，但不能继续放行新构建。

### 6.2 第一版素材边界

- 图片：PNG、JPEG、WebP，单文件不超过 50 MB。
- 视频：MP4、MOV、WebM，单文件不超过 2 GB；实际可解码性由 ffprobe/HyperFrames 检查。
- 品牌资料：Markdown、纯文本、PDF；PDF 只提取用户授权的本地内容。
- 网站：只处理用户明确提供且允许访问的 URL，抓取结果必须本地化并记录来源时间。
- 参考片：本地视频或明确授权的 URL，只提取导演 DNA，不复制受限内容。

素材账本记录原始路径、内容哈希、来源、授权说明、派生文件和使用场景。敏感本地路径不进入最终公开交接包。格式不支持、文件过大、损坏或网络抓取失败时，工作台必须指出具体素材并允许删除、替换或继续处理其他素材。

## 7. 错误与诚实状态

- 服务尚未启动：由 Codex 对话直接说明并启动服务；服务启动后浏览器才能打开工作台。已经打开的工作台若连接中断，则显示“导演工作台连接中断”和重试状态。
- 素材读取失败：指出具体文件和原因，保留其他已读取素材。
- Skill 加载失败：显示退化方案，禁止假装已经采用该最佳实践。
- 武器不兼容：退回候选状态并建议替代武器，不能直接进入成片。
- 技术检查失败：阻断交接，不能被用户豁免。
- 审美问题：允许返工、补素材或带理由接受，但问题必须留在交接单。
- LLM 审美能力未配置：明确显示“等待人工审片”，不能用规则结果冒充 AI 审美判断。

## 8. 审美评分与界面量化标准

### 8.1 工作台界面

- 1440×900 及以上桌面宽度中，样片舞台至少占主工作区宽度的 55%，首屏可见面积不低于 45%。
- 主行动按钮每个状态最多 1 个；同屏强调色不超过 1 个主色。
- 正文中文最小 14 px，关键状态最小 16 px，交互目标最小 40×40 px。
- 16:9、9:16 样片都必须完整适配舞台，不能被侧栏遮挡；重要文字和产品主体默认位于画面四周 8% 的标题安全区内，不得被裁切。
- 正文文字对比度至少 4.5:1，大字号文字至少 3:1；有意使用低对比度的装饰文字不得承担关键信息。
- 1440×900、1280×800 和窄屏三种浏览器快照都要人工审阅；控制台错误为零。

### 8.2 样片审美评分

每个关键帧和整段运动按 1–5 分评估：构图与视觉层级、品牌/内容适配、素材呈现、运动连续性、节奏与停顿、风格一致性、商业完成度。通过条件为平均分不低于 4.0，任何单项不得低于 3；低于阈值必须返工或由用户明确接受风险。

所有审美评分使用统一 scorecard schema，记录 build hash、评分来源（Codex / 独立模型 / 人工）、评分者或模型标识、时间、逐项分数、逐项理由、引用证据帧和总建议。确定性检测结果与主观评分分开保存。没有已配置且明确标识的评分者时，审美状态保持 `needs_review`，不能自动通过。

确定性检查同时覆盖：主体是否在安全区、文字与背景对比度、素材是否可见、裁切是否遮住主要对象、相邻场景是否有运动接力、最终停留帧是否完整。无法自动判断的构图和审美项必须显示为人工审片，不能伪造数值。

## 9. 验收标准

### 9.1 普通用户体验

- 首屏全部为中文，用户不需要理解 CLI、JSON、HTML 或 HyperFrames 命令。
- 用户能通过“Codex 对话 + 浏览器工作台”完成完整流程：在 Codex 中说想法和提出创意修改，在工作台中检查素材、确认方向、观看样片并做决定。
- 页面在常见桌面宽度下保持样片为视觉主角；窄屏退化为“对话 → 样片 → 判断”的单列顺序。
- 浏览器无控制台错误，操作进行中、成功和失败都有明确中文反馈。

### 9.2 导演能力

- 中文标题与项目文案真实进入样片，不再出现固定英文占位文案。
- 至少覆盖产品发布、无真人解说和网站展示三种 Codex 工作流样例。
- 每个样例都有明确 skill-load-plan、调性选择、storyboard、weapon-load-plan 和调用证据。
- 缺素材时审计必须报告缺失；有素材时能在关键帧中证明素材可见且裁切合理。
- 每个样例至少执行一轮用户反馈，例如“降低科技感”或“突出产品”；反馈后调性/分镜必须产生语义差异，HTML build hash 必须变化，关键帧必须能看出对应视觉变化。
- 使用同一输入重复构建时结果应保持确定；修改输入后不得复用旧批准或旧证据。

### 9.3 武器与审美资产

- 旧版 23 件可执行动画/模板资产全部进入迁移账本，但只有通过验证的资产进入新运行库。
- 第一批至少选择 6 件高价值武器完成 16:9 与 9:16 的 weapon bench、HyperFrames 检查和人工视觉评分。
- 每件迁移武器都有来源、许可证、参数 schema、适用场景、禁用场景、证据帧和版本。
- 8 种视觉调性均有中文预览标本，用户看到的是视觉示例和适用场景，不是 YAML。

### 9.4 后厨闭环

- 新建项目、需求 intake、素材读取、导演提案、构建、快照、技术审计、审美审片、批准和交接端到端通过。
- HyperFrames `lint` 与 `check` 必须为零错误；关键帧不得黑屏、空白或使用错误项目内容。
- 技术问题不可豁免；审美豁免必须记录用户理由和未解决风险。
- 固定模板测试只能证明基础设施，不能作为导演能力验收。

### 9.5 旧运行时隔离

- 新工作树不存在 `framepack-plugin/`、`framepack-e2e-test/`、Hermes hook 与部署脚本。
- 新 TypeScript 包不 import、spawn 或通过路径读取旧 Python plugin runtime。
- 所有选择性继承资产都位于新的宿主无关目录并出现在迁移账本中。
- CI denylist 和依赖扫描能够在重新引入旧运行时路径时失败。

## 10. 分阶段范围

### 10.1 真实性闭环里程碑

先用一个真实的产品发布项目证明导演链路：1 套主调性、3 件 proven 武器、真实中文需求与素材、一次用户反馈修改、双比例样片、审片和交接。该里程碑只证明架构与导演闭环，不对外称 Codex 第一版完成。

### 10.2 Codex 第一版完成标准

- 中文导演驾驶舱。
- 真实需求与素材驱动的项目状态。
- Skills 按需加载与执行收据。
- 旧版审美资产迁移账本。
- 第一批 6 件 proven 武器及其视觉证据。
- 三类真实工作流的端到端样例。
- HyperFrames handoff，不负责最终配音、字幕、混音和 MP4 生产。

只有上述第一版标准全部通过才可称“Codex 版本完成”。Hermes 与 Claude Code 适配、全部历史武器一次性升级、公共武器市场和多人协作不进入本阶段。
