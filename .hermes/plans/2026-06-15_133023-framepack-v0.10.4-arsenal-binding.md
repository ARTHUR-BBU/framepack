# Framepack v0.10.4 Arsenal Binding Contract Implementation Plan

> **For Hermes:** Use test-driven-development to implement this plan task-by-task. Do not skip RED → GREEN → REFACTOR. After implementation, use verification-before-completion before claiming done, and requesting-code-review before commit/release.

**Goal:** Build v0.10.4 Arsenal Binding Contract: reliable arsenal sync plus canonical weapon function metadata so Quality Audit can tell whether Manifest weapons are registered and called by their canonical functions.

**Architecture:** Keep Framepack inside its boundary: it creates/reconciles `.framepack/arsenal.json` and reports semantic risks, but never rewrites `index.html`. Move weapon function names into `core/builtin_weapons.py` as the single source of truth; add a shared project sync function in `core/arsenal_registry.py`; wire hooks and optional CLI sync through that function.

**Tech Stack:** Python 3.11, pytest, Hermes Plugin hooks, existing Framepack core modules.

## Acceptance criteria

1. Fresh project with `.hyperframes/expanded-prompt.md` but no `.framepack/arsenal.json` can be synced into a valid registry.
2. Projects without `.hyperframes/expanded-prompt.md` are not polluted with empty `.framepack/arsenal.json` by the new project-level sync helper.
3. Builtin weapon function metadata lives in `core/builtin_weapons.py`, not duplicated in `core/quality_audit.py`.
4. Registered arsenal entries include canonical `function` for builtin weapons.
5. Quality Audit still reports `manifest_weapon_not_called` as P1 when canonical function is absent.
6. HANDWRITE entries do not trigger function-call issues.
7. `framepack_quality_audit.py` remains read-only by default, but supports explicit `--sync-arsenal` mutation.
8. HyperFrames discovery commands still do not create arsenal files.
9. Full plugin tests pass with:
   `cd framepack-plugin && python -m pytest tests/ -q -o "addopts="`

```python
def sync_arsenal_from_project(project_dir: Path, plugin_dir: Path | None = None, plugin_version: str = DEFAULT_PLUGIN_VERSION) -> ArsenalSyncResult:
    """Ensure and reconcile `.framepack/arsenal.json` from project expanded-prompt.

    No-op when `.hyperframes/expanded-prompt.md` is missing, so empty projects are
    not polluted with Framepack state.
    """
    project_dir = Path(project_dir)
    expanded_path = project_dir / ".hyperframes" / "expanded-prompt.md"
    path = _registry_path(project_dir)
    if not expanded_path.is_file():
        return ArsenalSyncResult(False, "missing_expanded_prompt", path, [])
    try:
        content = expanded_path.read_text(encoding="utf-8")
        result = ensure_arsenal(project_dir, plugin_dir, plugin_version)
        warnings = list(result.warnings)
        data = load_arsenal(result.path)
        data, reconcile_warnings = reconcile_manifest(data, parse_execution_manifest(content), plugin_dir)
        warnings.extend(reconcile_warnings)
        save_arsenal(result.path, data)
        changed = result.changed or any(w.code != "handwrite_weapon" for w in reconcile_warnings)
        action = "synced" if result.action in {"created", "exists", "migrated"} else result.action
        return ArsenalSyncResult(changed, action, result.path, warnings, result.error)
    except Exception as exc:
        return ArsenalSyncResult(False, "error", path, [], error=str(exc))
```

Note: If exact `changed` semantics get awkward, tests should focus on file existence and registered content; avoid overfitting to `changed` when reconcile has no explicit changed return.
